# カラオケ動画のフレーム境界検証

## 30 fps での修正前後の比較

5秒の無音 WAV（モノラル、8 kHz、16 bit）と、3.700秒から4.100秒まで「FRAME 111」を出す合成キューを使用した。映像は640×360の透過MOV、歌詞は1行の follow、先行表示と保持はともに0 ms。同じ Windows ホスト、FFmpeg、Noto Sans JP で書き出し、デコードした RGBA のアルファが180以上の画素を数えた。フレーム番号は0始まり。

| エンジン | 110 | 111 | 112 | 122 | 123 | 124 |
|---|---:|---:|---:|---:|---:|---:|
| 修正前（`96e881a`、ASS/1） | 0 | 0 | 443 | 443 | 0 | 0 |
| 修正後（ASS/2） | 0 | 443 | 443 | 443 | 0 | 0 |

修正前のMOVのSHA-256は `36cf072a903b7cf9173483c4acd601757e50a05c8fef83eebd899b42c38153a4`、修正後は `cf7ee7882ada17144b37a3142183fccaa9ff95cb41dae64d960698e59ebd28b6`。

この比較に使った FFmpeg の SHA-256 は `3256173f3f8bffd7df12227c68adf68025edb1832273a9530688a7bb1ed8edec`、フォントは `5113756f8a3b5d01b2211025e267c50121e3b36f465b7bbaf3cdaf4c3430bfd0`。新ビルドで ASS/1 のレシピを再実行した結果も修正前の MOV と同一だった。

## 検証の再実行

- **フレーム計画**　リポジトリのルートで `dotnet run --project tests/TheoriaCast.Visual.UnitTests/TheoriaCast.Visual.UnitTests.csproj` を実行する。30・60 fps の全境界の時計変換、歌詞の状態遷移、音符の発音区間、SRT の行番号、出力検査の異常系を確認する。
- **実映像**　Visual API の Debug ビルドを用意し、Pillow が使える環境で `python tests/TheoriaCast.Visual.Tests/karaoke_boundaries.py --ffmpeg <ffmpeg.exe> --font <NotoSansJP.ttf> --output <検証先>` を実行する。入力JSON、無音WAV、境界のPNG、動画、測定値が検証先に残る。`THEORIA_VISUAL_ARTIFACTS` で .NET の成果物ディレクトリを指定できる。
- **旧レシピ**　旧ビルドを指定して上記に `--baseline` を付けると修正前を計測する。新ビルド側の実行に `--legacy-reference <修正前のboundary.json>` を加えると、旧レシピ再生成の全ファイルハッシュも比較する。
- **実曲と画面操作**　`verify_karaoke.py` は Music の WAV・歌詞・ガイド譜から3形式を書き出し、境界付近のサンプルと各動画の再生成ハッシュを確認する。`verify_karaoke_atelier.py` は Edge で SRT の取り込み、動画・レシピの保存と再生成を操作する。入力引数は各スクリプトの `--help` を参照。

合成データでは、各fpsにつき歌詞の境界前後と先頭・最終の計22フレームで両行の画素マスクを比較し、下線は離れた文字の間を横断する連続画素で判定する。バーと五線譜では孤立した1音について、再生線の前後各2フレームで開始端・符頭中心を測る。許容誤差は1フレームの移動量の半分未満。これらは選択したフレームの描画検査で、動画全体の再生成一致は別にファイルの SHA-256 で判定する。

## 実行結果

- 合成動画では30・60 fpsともに、歌詞の表示・消失、二行表示、先行表示と保持が競合する区間、下線の検査に合格。音符の位置の実測誤差はバーで0 px、符頭中心で最大0.5 pxだった。
- 196.799秒の実曲を1920×1080・30 fpsで書き出した。各形式で選択した7フレームを調べ、バー MP4（9,835,981バイト）、五線譜 MP4（14,496,100バイト）、透過歌詞 MOV（93,281,774バイト）のすべてで再生成時の全ファイル SHA-256 が一致した。
- Edge の Atelier から SRT とガイド譜を投入し、動画とレシピを保存して再生成ハッシュの一致を確認した。既存の Visual 基本・拡張・背景除去の回帰試験にも合格した。
- フォント名の不一致は HTTP 409、指定フォントにない字は当該ジョブの失敗として確認した。範囲外の歌詞では WAV が確定されず、破損したジョブがあっても後続の動画は完了した。成功時・失敗時とも一時フォントと一時動画が残らないことを確認した。
